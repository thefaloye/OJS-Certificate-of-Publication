# BIJPHGR Publication Certificate and Notification Plugin

Version 1.2.0 · OJS 3.5 (tested on 3.5.0-5) · PHP 8.2+ · Generic plugin

When an article becomes **publicly available**, the plugin issues a branded PDF
*Certificate of Publication* and e-mails the corresponding author a secure
download link. A QR code on the certificate opens a public verification page.

## Install

1. Copy the folder `bijphgrPublicationCertificate` to `plugins/generic/` (or upload the
   `.tar.gz` under *Website → Plugins → Upload a New Plugin*).
2. If you copied the folder by hand, register it so the tables are created:
   `php lib/pkp/tools/installPluginVersion.php plugins/generic/bijphgrPublicationCertificate/version.xml`
3. *Website → Plugins → Generic Plugins* → enable **BIJPHGR Publication Certificate**.
4. Open its **Settings** and fill in the signatory name (Editor-in-Chief) and publisher
   name. Optionally upload a signature image (PNG/JPEG ≤ 1 MB, transparent PNG is best).

**Until the signatory name and publisher name are set, nothing is issued or e-mailed.**
Articles published meanwhile are held as *pending* and released automatically the moment you
save complete settings. Back up the database and `files_dir` before installing.

## Certificates dashboard

Open it from the sidebar (**Publication Certificates**), from *Website → Plugins → Certificates*, or at
`/{journal}/bijphgrCertificates`.

- **Who:** journal managers, site administrators and editors can view, search and download.
  Only managers and administrators can resend or regenerate.
- **List:** summary tiles (total, sent, needs attention, failed, waiting, withdrawn), search by
  certificate number, title, author, recipient e-mail or article ID, filters, and 20 per page.
- **Detail page:** article and certificate facts, a plain-language "What now?" for the current state,
  every PDF version, and the full activity log with the user who did each action.
- **Resend e-mail:** new download link; the old one stops working. **Regenerate certificate:** new
  version from the current article details and signature; earlier versions are kept; no e-mail.
- **Bulk:** *Retry failed e-mails* and *Issue held certificates* appear when there is something to do.
- All actions are POST-only with CSRF protection and are written to the audit log with the acting user.

## Server requirements

- `files_dir` outside the web root (an OJS requirement). Certificates live in
  `files_dir/bijphgr-certificates/` and are never web-accessible.
- **`base_url` in `config.inc.php` must be your real public URL.** Queue workers and
  cron run without a web request, and the certificate's QR code and e-mail links are built
  from it.
- A working queue: either the built-in web job runner (`job_runner = On`, the default) or a
  cron entry running `php lib/pkp/tools/jobs.php run` every minute.
- Working outgoing mail in OJS (SMTP settings) and a journal contact e-mail address, used as
  the sender.
- Only PHP extensions OJS 3.5 already requires (including `mbstring` and `bcmath`). The QR code is
  vector (SVG), so `gd` is not needed.

## How it behaves

| Situation | Result |
|---|---|
| Article scheduled in an unpublished issue | Nothing. |
| Article/issue becomes published (any path: single, whole issue, scheduled date, API) | One certificate record, PDF generated by a background job, one e-mail. |
| Duplicate event, job retry, parallel workers | Still one record, one PDF, one e-mail (database-enforced). |
| No corresponding author (primary contact) designated | Certificate generated, e-mail marked *failed* with a clear reason. **No fallback to the first author.** Fix the publication, then resend. |
| Mail server down | Job retries (5 attempts); the certificate is not regenerated; status *failed* if all fail. |
| Published metadata corrected (title, authors, issue, date, DOI) | Certificate flagged, a **new revision** is generated and audited. Earlier PDFs are kept; the e-mailed link serves the latest. No extra e-mail. (Switch off in Settings.) |
| Article unpublished | Certificate *withdrawn*: download blocked, verification page says not publicly available and hides details. Republishing restores it without re-sending. |

Identifier format: `BIJPHGR-CERT-2026-000001` (sequential per journal/year, allocated
transactionally). Numbers are **not** secret: download and verification links use separate
random tokens (256-bit download token stored only as a hash; 160-bit verification token).

## E-mail template variables

`{$authorName}` `{$articleTitle}` `{$articleId}` `{$allAuthors}` `{$journalName}`
`{$journalUrl}` `{$volume}` `{$issue}` `{$publicationDate}` `{$doi}` `{$articleUrl}`
`{$certificateNumber}` `{$certificateUrl}`, plus `{$issueLine}` and `{$doiLine}`
(whole lines that vanish when there is no issue/DOI). Values are HTML-escaped.

## Data

Tables: `bijphgr_certificates`, `bijphgr_certificate_revisions`,
`bijphgr_certificate_counters`, `bijphgr_certificate_audit` (append-only; no secrets stored).
Records deliberately have no foreign keys, so they survive deletion of a submission.

## Not included yet (planned)

- Issuing certificates for articles that were published **before** the plugin was installed
  (a reviewed, no-e-mail back-fill is planned; nothing is sent to past articles automatically).
- Formal retraction handling (OJS 3.5 has no retraction status; *unpublished* is handled).
- Per-version policy: today every newly **published version** of an article gets its own
  certificate and e-mail. Say if you want a certificate but no e-mail for later versions.

## Bundled third-party code

`lib/chillerlan/php-qrcode` 5.0.5 (Apache-2.0 or MIT) and `lib/chillerlan/php-settings-container`
3.2.1 (MIT) generate the QR code (OJS ships mPDF but no QR encoder). PDF rendering uses the
mPDF already bundled with OJS.
